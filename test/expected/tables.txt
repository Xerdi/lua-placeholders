Case 1: All columns referenced (baseline)
 Description     Price
 Apples          1.50
 Oranges         2.00

Case 2: Subset of columns referenced
Omitting \price in the row macro should drop the column silently — the row
still iterates and the description column still renders. The unreferenced cell
value is computed but never expanded.
  Description
  Apples
  Oranges

Case 3: Columns referenced in reverse order
With string replacement, swapping the order in the row macro could interfere
when one column name is a prefix of another. With the macro-binding approach,
order is irrelevant.
 Price Description
   1.50 Apples
   2.00 Oranges

Case 4: Underscore column names with \ExplSyntaxOn
The underscore table declares three columns: item (a number), item_name
and unit_price. Two issues appear:

  • \item is a prefix of \item_name. String-replacement substituted \item
    first, mangling \item_name. The macro-binding implementation defines
    each column as its own control sequence, so prefix collisions are impossible.
  • Without \ExplSyntaxOn, TEX reads \item_name as \item followed by the
    subscript token _ and the letters name, which fails. Wrap the row macro
    in \ExplSyntaxOn …\ExplSyntaxOff to flip _ to letter catcode at parse
    time so \item_name tokenises as one control sequence.
   #    Item      Unit price
 1.00   Widget          9.99
 2.00   Gadget         14.50

Case 5: Special characters in cell values
A cell may carry whatever TEX can render — but the YAML author still has
to obey TEX’s lexical rules. In particular, a literal % must be written as \% in

the payload, otherwise TEX sees the unescaped % and treats the rest of the line
as a comment. UTF-8 characters such as € pass through unchanged because
LuaTEX’s input encoding is UTF-8 by default and the body font has the glyph.
Old string-replacement was also vulnerable to a Lua-pattern hazard: % in a
cell value would be interpreted as a back-reference by string.gsub’s replace-
ment argument. With token.set_macro the value is just bytes, so this class of
breakage is gone.
 Label       Note
 VAT rate 21%
 Subtotal    € 1 234,56
 Mixed       € 50 + 21% VAT

Case 6: List cell — type survives, accessed via
\forlistitem
A column may itself have type list. The cell isn’t flattened to a string; instead
the row macro accesses it through the list’s own interface, exactly like a top-
level list parameter. Below the items column in each row is iterated with
\forlistitem.
  Customer Items
  Alice         • Widget • Gadget
  Bob           • Sprocket • Cog • Lever

Case 7: Object cell — type survives, accessed via
\paramfield
Likewise, a column of type object keeps its field structure. Accessing the
shipping cell with \paramfield per field, or the paramobject environment
to bind every field as a local macro, both work because lookups inside a row
consult the active row’s cells before the global namespace.
 Customer Street              City
 Alice          1 Main St Springfield
 Bob            2 Oak Ave Shelbyville
Same payload, accessed with the paramobject environment:
 Alice lives at 1 Main St in Springfield.
 Bob lives at 2 Oak Ave in Shelbyville.
